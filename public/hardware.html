IR Remote reverse engineering

► ◄

Summary

Need

The need for this project arose after I hosted my own local music server and could play music from my phone, but still needed to turn on the receiver and switch inputs manually. I figured that if I could salvage an IR LED from an old remote and connect it to an ESP32 using Bluetooth or Wi-Fi, I could control the receiver remotely.

The Project

I used an IR LED from an unused remote and connected it to my oscilloscope to view the data sent by the receiver's remote for commands such as ON and INPUT. I then measured the pulse lengths and wrote a C++ program to mimic this behavior. When I tested it, it did not work. At first, I attributed this to the strength of the IR LED, so I reduced its resistance in the hope of improving the signal. However, this yielded no success. Upon further research, I discovered two problems. First, my timing for interpreting a 1 and 0 was slightly off, and second, the signal used a 40 kHz carrier wave. I fixed the first problem by adjusting the timing, and fixed the second by writing a function to oscillate a signal at 40 kHz when it was specified to be on. After testing this, it worked.

My process for sending bits to the IR LED was rudimentary, so I improved it by using bitwise operations on a 16-bit word of data to send a bit and then shift the remaining bits until none were left. Next, I researched the Bluetooth capabilities of the ESP32 and found a suitable BluetoothSerial library. I then downloaded a serial terminal on my phone and was able to send commands to the receiver through character input over Bluetooth!

Skills

  • Reverse engineering
  • Troubleshooting
  • Bluetooth
  • Hardware/software interface
  • Oscilloscope triggering, measurement, and analysis
  • FreeRTOS queues
  • ESP32

DIY Streamdeck (UART/USB)

► ◄

Summary

Need

I often have many manual applications and keypresses I want to accomplish when I start my pc, or various programs. I decided to create a hardware device that would function as a keyboard and would have buttons that could be programmed to execute certain keypresses or strings of keypresses.

The Project

To start, I discovered I had a CP2102 USB-to-UART bridge already in my possession, so I connected it to the UART2 port of the ESP32. I then wrote basic FreeRTOS functionality to detect button presses and send them to a queue. When a button was pressed, it triggered serial output from the UART port indicating that a button had been pressed. Upon further research, I realized that I needed this device to appear to the computer as a HID (Human Interface Device) in order for it to function as a keyboard. So, I plan on upgrading to a CP2110 which has this feature and should mean button interrupts can trigger HID events, such as keyboard presses, as described in the OSdev wiki
